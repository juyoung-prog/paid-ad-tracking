# 페이드 광고 트래킹 대시보드 (Paid Ads Tracking Dashboard)

> 메타/틱톡 페이드 광고의 현황과 성과를 한 눈에 파악해 기록/보고에 드는 인지적 부담과 중복 작업을 줄이는 대시보드

## 배경 및 목적

- 왜 만드는가 (문제/기회)
  - 현재 메타(조지아 계정, 플로리다 계정) + 틱톡(통합 1계정)으로 페이드 광고를 운영 중이며, 매장은 조지아 10개(G01~), 플로리다 5개(BF1~)로 향후 계속 추가될 예정
  - 광고가 1개일 때는 문제없지만, 여러 개가 동시에 돌아가면 "어떤 광고 · 어떤 계정 · 어떤 플랫폼 · 기간 · 예산 · 목표 · 성과"를 계속 기억/추적해야 해서 인지적 부담이 큼
  - 캠페인 기록이 5개 채널(트렐로 / Marketing Log & Budget 시트 / 이벤트별 시트 / 연간 마케팅 플랜 시트 / 성과보고용 별도 엑셀)로 분산되어 있어 중복 기록이 발생
  - 성과보고 시점마다 메타·틱톡에서 수동으로 데이터를 찾고 다운로드해야 하며, 어떤 지표를 봐야 할지 매번 고민되어 결국 전체 데이터를 다 받는 비효율이 반복됨
- 기대 효과
  - 광고가 여러 개 동시에 돌아가도 현황(진행중/예정/종료, 매장, 기간, 예산, 목표)을 시각적으로 한 눈에 파악 → 인지 부담 감소
  - 성과 보고에 필요한 데이터를 구조화해 기록 → 보고 시점의 재탐색/재다운로드 최소화
  - 광고 관련 기록을 대시보드 하나로 통합 → 여러 채널에 나눠 기록하던 중복 제거 (트렐로 연동 없이 대시보드가 광고 기록의 유일한 지점이 됨)

## 핵심 기능

| # | 기능 | 설명 | 우선순위 |
|---|------|------|---------|
| 1 | 광고 현황 대시보드 | 진행중/예정/종료 광고를 플랫폼(메타/틱톡)·계정(조지아/플로리다/틱톡통합)·매장·기간·예산·목표 기준으로 시각화 | 필수 |
| 2 | 광고 등록/관리 폼 | 광고 생성 시 플랫폼, 계정, 대상 매장(단일/복수/전체), 기간, 예산, 목표를 구조화된 폼으로 1회 입력 | 필수 |
| 3 | 매장 마스터 관리 | 조지아(G01~), 플로리다(BF1~) 매장 코드를 관리하고 신규 매장 추가를 지원 | 필수 |
| 4 | 성과 기록 및 보고 | 광고 종료 후 핵심 성과 지표를 입력/조회하고 보고용으로 정리·내보내기 | 필수 |
| 5 | 알림/경고 | 광고 종료 임박(D-day) 알림, 종료 후 성과 데이터 미입력 알림, 동일 기간·동일 매장 캠페인 중복 알림 등 | 필수 |
| 6 | Google Sheets 연동 | Marketing Log & Budget, 이벤트별 시트, 연간 마케팅 플랜과의 연동 방식 (범위는 추후 확정) | 선택 |
| 7 | Meta/TikTok Ads API 자동 수집 | 성과 데이터를 플랫폼에서 자동으로 가져오는 연동 (1차 범위 제외, 우선 수동 입력) | 선택 |

## 대상 사용자

- 주요 사용자: 페이드 광고를 직접 운영·기록·보고하는 마케팅 실무자 본인 (1인 운영)
- 보조 사용자: 팀원 (향후 함께 사용할 예정 — 매장 확장에 따라 팀 단위 사용을 염두에 둠)

## 기술적 범위

- 포함
  - 광고 현황 대시보드 UI (필터: 플랫폼/계정/매장/기간/상태)
  - 광고 등록 폼 및 매장 마스터 데이터 (동적 추가 가능해야 함)
  - 알림/경고 로직 (종료 임박, 성과 미입력, 중복 타겟팅)
  - 성과 데이터 수동 입력 및 보고서 뷰/내보내기
  - 동일 회사(BeautyMaster)의 [Influencer Tracking Dashboard](https://github.com/juyoung-prog/Influencer-Tracking)에서 확립된 커스텀 테마 토큰과 운영 툴 컴포넌트 패턴 재사용/참고 (아래 근거 참고)
- 제외 (1차 범위)
  - 트렐로 연동 (대시보드를 광고 기록의 원툴로 사용, 외부 도구 연동 없음)
  - Meta/TikTok Ads API를 통한 성과 데이터 실시간 자동 수집 (추후 확장 검토)
  - Google Sheets 각 시트와의 완전 자동 동기화 (연동 범위는 Phase 2에서 구체화)
- 제약사항
  - 매장이 계속 추가되므로 매장 마스터는 코드 체계(G01, BF1 등)를 유지하며 확장 가능해야 함
  - 캠페인은 단일 매장 타겟(예: 그랜드 오프닝), 복수 매장 타겟, 전체 매장 타겟 세 가지 케이스를 모두 지원해야 함
  - 인스타그램(메타)은 조지아/플로리다 계정이 분리되어 있고, 틱톡은 통합 1계정이라는 비대칭 구조를 데이터 모델에 반영해야 함
  - 1차 범위는 단일 사용자 기준으로 설계하되, 향후 팀원 합류 시 다중 사용자(권한/역할 구분)로 확장 가능한 구조를 고려해야 함
  - 비주얼/컴포넌트는 Influencer Tracking Dashboard와 통일감을 유지해야 함 — 구체적 재사용 목록은 Phase 2(ux-flow)의 컴포넌트 리스트, 세부 토큰은 Phase 3(visual-direction)에서 확정
  - 빌드 여부는 Google Sheets/Notion 등 노코드 대안과 비교 검토 후 커스텀 대시보드로 확정 (Influencer Tracking Dashboard와의 디자인 시스템 통일성, 커스텀 알림/pacing 로직 확장성이 결정 근거)
  - 매장 귀속(attribution) 원칙: `multi_store`/`all_stores` 캠페인은 매장별 예산을 분배하지 않음 — 캠페인 단위로만 금액 집계, 매장 뷰에는 해당 매장을 커버하는 캠페인 목록만 표시 (상세는 02-ux-flow.md 참고)

## 성공 기준

- 여러 광고가 동시에 돌아갈 때 현황(무엇이, 어디서, 언제부터 언제까지, 얼마의 예산으로 진행 중인지)을 한 눈에 파악할 수 있다 (인지적 부담 감소)
- 성과 보고 시 메타/틱톡을 오가며 데이터를 재탐색·재다운로드하는 시간이 줄어든다
- 광고 관련 기록이 대시보드 하나로 통합되어, 트렐로나 다른 시트에 별도로 남기지 않아도 된다
- 광고 종료 임박·성과 미입력 등 놓치기 쉬운 상황을 알림으로 사전에 인지할 수 있다
- 같은 회사의 Influencer Tracking Dashboard와 시각적으로 통일된 느낌을 준다 (같은 팀이 만든 내부 툴군으로 인지됨)

## 참고: Influencer Tracking Dashboard 재사용 근거

`github.com/juyoung-prog/Influencer-Tracking`을 확인한 결과, 동일한 vibe-design-starter-kit 기반이며 같은 회사(BeautyMaster, 매장 코드 `G10` 등 일치)를 위해 이미 "내부 운영 툴" 비주얼 방향이 확립되어 있음.

- **톤앤매너**: Operational · Clean · Status-first · Low friction (Linear/Notion/Vercel 스타일 레퍼런스) — 운영자가 하루 여러 번 보는 화면이라는 성격이 이 프로젝트와 동일
- **재사용 가능한 커스텀 테마 토큰** (`src/styles/themes/default.js`): `success`/`warning`/`error` 상태 컬러, KPI 숫자용 `fontVariantNumeric: tabular-nums`, Outfit Variable 헤딩 폰트, Chip `4px` 라운딩(pill 금지) 등
- **재사용 후보 컴포넌트**: `KpiBar`(현황 요약 바) → 광고 현황 요약에 대응, `StoreBreakdown` → 매장별 광고 분해, `InfluencerFilterBar` 패턴 → 광고 필터 바, `SyncStatusBar` → 데이터 갱신 상태 표시, `AppShell`/`StickyAsideCenterLayout` → 2컬럼 레이아웃 골격
- **적용 방식**: 코드를 그대로 복붙하지 않고, `component-work` 스킬 워크플로우를 통해 이 프로젝트의 컴포넌트 taxonomy에 맞게 이식 — 상세 매핑은 Phase 2(ux-flow) 컴포넌트 리스트에서 진행
